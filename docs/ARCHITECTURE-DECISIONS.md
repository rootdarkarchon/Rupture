# Current architectural decisions

These decisions describe implemented constraints. Their mechanisms and owners are in the linked guides; they are not a roadmap.

| Problem | Current solution | Consequences / tradeoffs | Invariants to preserve |
| --- | --- | --- | --- |
| Equipped bodies and clothing differ in topology, skinning and LODs. | Capture actual renderers and immutable source meshes; classify using real anatomical bones and shared cut candidates. [Geometry](ARCHITECTURE-GEOMETRY.md) | Readability, malformed boundaries and incompatible anatomy can prevent a visual. Capture/cache cost is paid locally. | Do not invent missing anatomy or accept an incomplete destructive batch because one LOD succeeded. Preserve untouched channels and borrowed assets. |
| Requested clothing readability recovery must decompress LZMA without delaying headless startup or depending on Unity's private decoder ABI. | Vendor the public-domain LZMA SDK 26.03 C decoder in the existing native DLL; use its versioned codec export, with a decoder-side buffered managed fallback. Share garment discovery results across requests and skip clothing preparation on headless. [Clothing preparation](ARCHITECTURE.md#clothing-bundle-preparation) | Native decoding measured within 0.59% of installed Unity across 1,137 local LZMA bundles. Container parsing, rewrite and retained CPU mesh data still have costs. | No Unity deserializer patch or private decoder entry point in production; no eager clothing preload or compatibility bridge. Preserve original files, validate exact input/output sizes, and fall back to original loading on failed recovery. |
| Several renderer/LOD mutations must become one visible injury. | Stage limb output and adopt with `CommitTransaction`; head replacement has its own validated lifetime/restore path. [Geometry](ARCHITECTURE-GEOMETRY.md#commit-rollback-and-cleanup) | Temporary memory and preparation latency; postcommit decals/blood are separate failure scopes. | Roll back failing adoption operations; transfer resource ownership exactly once; never describe cosmetic failure as undoing a committed cut. |
| Living fracture visuals need to follow treatment, equipment and pose. | Add collars/bone ends and LOD membership without replacing the body mesh. [Geometry](ARCHITECTURE-GEOMETRY.md#additive-living-fractures) | Surface fitting/covering selection is required; appearance depends on actual clothing. | Remove only owned LOD entries/anchors; no collider change; dispose on treatment/controller replacement/death. |
| Shipping/generated meshes would couple transport to local asset/render state. | Authority sends decisions, local coordinates and seeds; graphical peers generate geometry and local gibs. [Multiplayer](ARCHITECTURE-MULTIPLAYER.md) | Rendering can fail or differ locally; procedural gib trajectories are not authority synchronized. | Authority owns outcomes; do not add mesh/particle/texture replay implicitly or treat local visual success as shared state proof. |
| Corpse simulation must have independent scheduling while EFT gameplay continues to find the corpse. | Standalone PhysX owns dynamics; native kinematic shells retain gameplay/query identity. [PhysX](ARCHITECTURE-PHYSX.md) | Geometry capture/cooking, shell synchronization and failover bookkeeping are necessary. | Commit only with complete supported rig/environment; retain terrain semantics; restore native state on failure; weapon stays independent. |
| Native scene mutation and asynchronous cancellation need a single resource owner. | Dedicated scene-owner thread and explicit publication/take/close for transient results. [PhysX](ARCHITECTURE-PHYSX.md#owner-thread-and-publication) | Queue/wait cost; timeout may quarantine an instance and retain loaded native code. | One in-flight step, no Unity access on owner, no unloading under executing code, exactly one actor owner across cancellation. |
| Network motion and local hits have different latency needs. | Immediate local prediction followed by complete kinematic authority playback one observed interval behind; reliable terminal pose. [Multiplayer](ARCHITECTURE-MULTIPLAYER.md#motion-prediction-and-settle) | Buffer delay and sequence/echo bookkeeping; incomplete snapshots are discarded. | Apply whole body sets; do not block usable motion on late start metadata; suppress echoes; client timers cannot decide settle. |
| Solo loading must not require Fika types. | Core contract plus conditionally loaded adapter. [Multiplayer](ARCHITECTURE-MULTIPLAYER.md#runtime-selection) | Reflection/version checks and explicit startup failure handling. | No core Fika reference; an adapter failure in a Fika session must not silently run solo authority. |
| Shared visual policy must match while machine costs/debug choices differ. | Sixteen ordered validated authority values; graphical-host settings or the first headless requester snapshot, with an explicit headless-local override. [Multiplayer](ARCHITECTURE-MULTIPLAYER.md#handshake-protocol-and-configuration) | Client/headless UI values can be overridden in memory; raid start waits for adoption/broadcast, and configuration serialization needs save/restore handling. | Validate atomically, preserve wire order/revisions, save local preferences, restore on network reset; keep casing and diagnostic settings local. |
| Visual capacity is finite while native bleeds may persist. | Independent logical stream table and bounded emitter pools; headless runs logical handling. [Blood](ARCHITECTURE-BLOOD.md) | Some effects are temporarily invisible; restore is budgeted. | Eviction is not a stop; stop publishes once; no headless graphics allocation; treatment stops supply without erasing native paint. |
| Unity upload/bake and native setup cannot all be split into tiny jobs. | Managed snapshot workers plus explicit atomic main-thread/owner operations under soft scheduling budgets. [Geometry](ARCHITECTURE-GEOMETRY.md), [PhysX](ARCHITECTURE-PHYSX.md) | A single operation can exceed frame budget; skin baking, mesh application and some setup remain synchronous. | Document actual blocking boundaries, keep workers off Unity objects except the deliberate collider prebake, and measure before claiming reduced frame cost. |

Changes should be validated at the owning boundary, then in the complete lifecycle that consumes it. A topology fixture, packet round-trip or bridge test proves its own contract; it does not establish live appearance, callback scheduling or cross-peer acceptance.

## Rejected head-wound CSG experiment

The pinned pb_CSG 2.0.0 spike failed its material/geometry gates, and the high-poly case exceeded its 100 ms timing gate. Production uses the specialized wound cutter instead of a runtime third-party CSG dependency. The [performance guide](PERFORMANCE.md#rejected-head-wound-csg-experiment) retains the source pin, workload and measurements, plus the specialized pre-stitch fixture whose timing pass was superseded by visual review. Timing success alone is insufficient to adopt wound geometry.
